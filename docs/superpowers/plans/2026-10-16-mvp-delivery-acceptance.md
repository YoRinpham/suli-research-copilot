# 溯理 SULI 轻量交付验收

目标：尽快确认用户能通过正常界面完成一次“论文 → 实验计划 → 数据分析 → 正式报告”，并能重新打开和导出成果。本版替代原 8 关卡计划。

范围：当前本地环境、仓库现有两篇合成 PDF 与 synthetic_scores.csv。只处理阻断流程、来源错误、统计错误和导出失败；保留人工科学审核。以下勾选对应实际完成情况，验收于2026-10-17完成，详见唯一验收记录。

## 1. 基础检查

- [x] 确认前后端及数据库可用，前端连接实际后端地址。
- [x] 核对并修复已知 Landscape 提示版本与测试预期不一致的问题。
- [x] 跑后端默认测试、前端测试、类型检查和构建；保存结果。跳过的数据库/真实模型测试如实记录，不能算通过。

从仓库根目录依次执行，失败时先处理再继续：

```powershell
Set-Location backend
..\.venv\Scripts\python.exe -m pytest -q
Set-Location ..\frontend
npm test
npx tsc --noEmit
npm run build
Set-Location ..
```

通过：服务可访问，以上检查零失败。后续完整流程实际验证当前数据库、模型和嵌入调用。

## 2. 跑通一次完整流程

- [x] 新建一个合成验收项目，上传两篇 PDF，完成索引、检索和 Evidence 选择。
- [x] 生成并人工审核 Claim、Landscape，选择 Gap 和 Hypothesis，接受 ExperimentPlan。
- [x] 上传合成 CSV，审核与计划相符的分析方案，执行分析并生成一张图表。
- [x] 生成并人工审核 ResultInterpretation，再生成并接受 ResearchReport。用户追加永久删除两张图后，已针对剩余一张图完成新解释及报告的修订与人工接受。

由一位用户按上述步骤操作，开发者只观察、记录问题；不能靠改数据库或临时脚本补齐对象。实际统计方法必须与计划一致；若不一致，通过正常修订与审核处理后再分析。现有 Route A 描述统计不能冒充其 Plan 规则已经执行。

通过：正常界面能从头完成到已接受报告。出现阻断问题就修复并重跑受影响阶段；改动使上游失效时，从失效点重新开始。无阻断时不额外增加测试轮次。

## 3. 核对报告并复查成果

- [x] 报告包含问题、假设、计划、数据方法、结果、图表、解释、限制和来源；明确标为合成示例。
- [x] 检查全部报告引用可解析；至少沿一条关键陈述完整回到 Evidence、原文和 PDF 物理页，核对内容是否支持该陈述。
- [x] 核对报告数值与已存统计结果一致，图表对应同一数据版本，结论没有把合成结果当成现实证据。
- [x] 导出 Markdown 和 HTML，检查正文、图表与来源链接。当前链接依赖后端服务，交付说明必须写明访问方式；缺图或关键断链要修复。
- [x] 刷新页面，并正常重启验收服务一次；重新打开同一项目、查看来源，再次导出报告。无需重新生成或计算。

通过：报告内容完整，导出可用，重启后成果仍可读取和再次导出。这里只验证一次全流程与成果恢复，不宣称已经证明多次新项目运行的成功率。
