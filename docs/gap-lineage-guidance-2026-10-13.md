This isolated proposal is not deployed. It addresses demonstrable instructions and feedback limitations after Run `2bb8781b-d8c0-4f95-94d4-835f33c062a5` failed initial Evidence/Claim membership and then foreign-item membership. It does not reconstruct discarded wording, batch cardinality or offending IDs, identify a real object in another project, explain earlier transport failures, or establish a model mechanism.

Gap generation changes from `m4-v3` to `m4-v4`. Its full static prompt bundle digest includes generation, structured repair, unchanged advisory/assessment repair, and every fixed feedback instruction. Claim, Landscape, Hypothesis and Plan bundle identities stay unchanged. `m4-gap-v2` remains unchanged: its public schemas, source encoding `gap-context-v1`, capacity semantics, validation predicates and canonical persistence contract do not change. No migration, public field, provider interface, configuration or dependency is added.

Generation and repair explain the existing joint contract: exact canonical item IDs from current rows; explicit Claims within the chosen items' Claim union; all cited Evidence within both the item-allowed Evidence union (including inherited Claim sources) and the explicitly cited Claims' Evidence union. Integer row references are decoded to the correct domain IDs. Claim support/challenge roles remain distinct from Gap motivation/challenge roles. A Gap needs legitimately motivating support, separate disjoint roles, conditions and uncertainty. Unsupported candidates remain rejectable; no automatic Claim addition, ID replacement or role promotion occurs.

Three existing lineage failures now raise a Gap-only `ValueError` subtype with the same fixed messages. The actual batch validator attaches a zero-based index. Shared generation opts into feedback only for `gap_generation`, after a validation failure. The one existing repair receives a fresh replacement task from unchanged sources; it receives no prior candidate text. It cannot promise to preserve discarded wording. Codes are fixed `gap_foreign_landscape_item`, `gap_incomplete_lineage`, `gap_evidence_claim_mismatch`, with `gap_generation_invalid` as fallback. Index is strict integer 0–9 or null. Extra fields and forged model contents are rejected at capture. Unknown exceptions cannot supply arbitrary attributes, text, fields or identifiers. Feedback is independent of diagnostic collectors and logging.

The structured repair/two-call generation limit, advisory behavior, public error categories, legacy attempt accounting, diagnostic capture-time sanitization and failure isolation remain intact. Every candidate still passes lineage and exact capacity admission before any advisory; negative advisory judgments remain visible; atomic persistence and human selection remain unchanged. Existing originating-Run fencing and cancellation limitations are not repaired.

Synthetic/corpus-bounded commanded motion, physical conformity, nominal rotation, work, measurement performance and dependence limitations remain unchanged.
